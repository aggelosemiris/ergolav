# Backend: Nocturne

Supabase (Postgres 17, Auth, PostgREST). Local stack via `supabase start`; schema in
`supabase/migrations/20261018000001_init.sql`; seed (catalogue, curated playlists, local demo
account) in `supabase/seed.sql`, generated by `scripts/generate-catalog.mjs`.

## Auth
- Email + password through Supabase Auth; display name stored in `profiles` (created by a trigger on `auth.users`).
- Sessions in cookies via `@supabase/ssr`; `proxy.ts` refreshes them on navigation; server components verify the
  user with `auth.getUser()`.
- Local config turns email confirmation off (`supabase/config.toml`). On a hosted project with confirmation on,
  sign-up shows a "check your inbox" screen and the link returns to the app.
- Not built: password reset, OAuth providers, account deletion UI (deleting the auth user cascades every row).

## Database and access rules
- 13 tables, every one with RLS (see `architecture.md` for the matrix). Catalogue is read-only to clients.
- Ordered playlist edits go through `playlist_add_track / playlist_remove_track / playlist_move_track`:
  `security invoker` (RLS still applies), ownership asserted, the playlist row locked to serialise edits,
  positions kept contiguous; the position uniqueness constraint is deferred so moves commit atomically.
- Search: `search_catalog(q)` (unaccent + trigram word similarity), runs under the caller's RLS, so other
  users' private playlists never appear.
- Tested with two users in `e2e/security.spec.ts`: B cannot read A's private playlist or likes, cannot rename,
  delete or edit A's playlists through tables or functions, cannot forge rows for A; anonymous users cannot write.

## Media
- Stream URLs live in `track_streams` (url, mime, bitrate, licence, source), apart from metadata and artwork.
- Demo audio and art are served from `public/media/` (audio is generated, not committed).
- Supabase Storage is not used yet: user uploads are listed as not built.

## Payments, email, jobs
None in this slice.

## Security checklist
- [x] secrets only in env vars; `.env*.local` ignored; only the anon key reaches the browser
- [x] input validated: zod on auth and profile forms; length checks in playlist forms and as DB `check` constraints
- [x] authorisation on every read and write via RLS, tested with a second user
- [x] post-login redirect limited to same-site paths (`lib/redirect.ts`, unit tested)
- [ ] rate limits: relies on Supabase Auth's built-in limits (`[auth.rate_limit]`); no app-level limits
- [x] no webhooks
- [ ] uploads: not built
- [x] no user data in URLs (ids only) or logs
- [x] `npm audit --omit=dev`: see README test results
- [ ] privacy policy: not written (no processors beyond Supabase and the host)
